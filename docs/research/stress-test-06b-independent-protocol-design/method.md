# Method

## Contamination boundary

The supplied transcripts are preserved byte-for-byte. Only content produced before Pictiq disclosure is treated as independent design evidence:

- **Phase A:** initial protocol architecture;
- **Phase B:** the model's self-critique;
- **Phase C:** its v0.2 revision.

**Phase D** compares the design to Pictiq after disclosure. It is useful for documenting hypotheses and claimed differences, but is excluded from independent-convergence counts.

## Analysis steps

1. Extract initial choices across purpose, core size, visual metaphors, grammar, composition, dialogue, quantity, direction, context, names, governance, human/machine representation, scale and safety.
2. Record each self-identified weakness and whether v0.2 narrowed, removed or merely restated it.
3. Count a theme as `3/3`, `2/3`, or `1/3` only when supported in independent material.
4. Compare the resulting themes with current Pictiq normative files: `spec/PROTOCOL.md`, `spec/GRAMMAR.md`, `spec/NUMERIC_NOTATION.md`, `spec/PICTIQ_MESSAGE_SCHEMA.md`, and `spec/PROFILES.md`.
5. Treat all architecture proposals as hypotheses. No mechanism is adopted.

The unit of analysis is an authored model response, not a product benchmark. The study contains no human comprehension measurement, rendering validation, or controlled comparison of visual stimuli.
