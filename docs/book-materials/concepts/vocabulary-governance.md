# Vocabulary governance: need before vocabulary

The Web/UI Stress Test reconciliation produced an important book/research lesson: a stress test should not mechanically become an icon wishlist.

Pictiq now uses the **NEED-BEFORE-VOCABULARY** rule: try existing primitives, composition, context, polysemy, and intentional omission before adding a new symbol. A plausible future use is not enough.

This protects small vocabulary, discoverability, zero-training entry, semantic economy, and combinatorial reuse. It also keeps Pictiq from becoming a pictogram dictionary.

The Web/UI review is the clean example. Loading became `time`; save/download uses contextual down; publish/upload uses contextual up; settings uses tools; empty state becomes `no + content`; notification becomes communication plus attention. The one accepted addition was `action_change`, because a UI-specific edit problem exposed a broader universal CHANGE primitive.

`DEFERRED_UNTIL_NEEDED` records plausible future concepts without creating canonical vocabulary. Current examples include archive, IT/system, and video.
